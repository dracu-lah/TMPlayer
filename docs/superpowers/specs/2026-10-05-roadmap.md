# TMPlayer 2.0 roadmap: localization, onboarding everywhere, competitive parity

## Context
GitHub issue #2 asked for Spanish. The user widened the request to treating TMPlayer as a product:
- localization with language detection on every device and on the site;
- onboarding on every device;
- the features and UX that competing Telegram TV apps, general media players and Netflix-class streaming apps have and TMPlayer lacks;
- a site and distribution that let people find it.

Research (2026-10-05, five agents) found:

**The market.** Every serious Telegram-video competitor is Android-only and closed source, and most charge money:
- Echogram (50K+ installs, freemium);
- TvGram (50K+);
- Tevegram (1M+ installs but 2.3★, with complaints about freezes and paywalls);
- VelaTV (subscription);
- "TMP - Telegram Media Player" (ads, on the Amazon Fire TV store; its name is close to ours);
- TV for Telegram on tvOS (paid).

The only cross-platform rival is TeleDrive, which is a drive, not a player. **TMPlayer's moat is that it is free, open source and ad-free, runs on desktop, uses seek-aware streaming, and has filters and a watched list.**

**What TMPlayer already has** (inventory from the code): resume, a Continue tab, autoplay next with a countdown (phone and desktop only), SxxEyy parsing (`core/.../data/MediaName.kt`), track memory per series, search inside a chat and across chat names (voice on TV), playback speed, aspect/zoom, frame-rate matching on TV, phone gestures, PiP, desktop keyboard shortcuts with `?` help, themes, the download queue with a storage meter, watched and favourites, skeleton and empty states, opt-in Sentry on Android.

**What is missing.** Ranked by research value per effort:
- localization;
- desktop onboarding;
- subtitle and audio delay;
- subtitle styling settings;
- volume boost;
- a sleep timer / "still watching?";
- the next-up card on TV;
- a series view and a Home with rows;
- a detail panel;
- search across all chats for videos, and recent searches;
- auto-delete of watched downloads;
- online subtitles;
- posters and metadata;
- trickplay;
- in-app feedback;
- "what's new" after an update;
- localized site pages, OS-detected downloads, a changelog, community and donation links, SEO guides, and more install routes (Fire TV, IzzyOnDroid, winget, Flathub, Amazon).

**Deliberately not copied:** preview autoplay on focus, profiles and kids mode, ranked or recommendation rows, rotating hero carousels, download quality choice (Telegram files have one quality), audio-fingerprint skip intro, theme engines, casting (L effort, revisit later). The Android TV Watch Next row is optional: Google retires the legacy API in H2 2027 and moves to the Engage SDK.

**Working rules for every phase:**
- **Stop at every CHECKPOINT**: commit, report in a few lines, and wait for the user to compact and say "continue".
- Never run `langsync`, cut a release, or submit to a store or registry without the user's go-ahead in that session.
- Push freely. Release only on request, after the release cadence guard.
- No em or en dashes anywhere. Screenshots are WebP q88 (CLAUDE.md).
- From Phase 1 on, every new UI string goes into `en.json` and never into a literal.
- Bulk edits use grep, sed, perl and jq pipelines (Part 3), not hand edits.

## Part 2. Architecture

### 2.1 Localization
- **Catalog:** `core/src/commonMain/resources/i18n/<tag>.json`, with `en.json` as the source of truth.
- **Format:** keys namespaced by screen, ICU MessageFormat (`{count, plural, one {# video} other {# videos}}`).
- **langsync:** `langsync.json` (app) and `langsync.site.json` (site) are already in the repo root. Both carry a list of names that are never translated. `.langsync-state.json` is committed, and reviewed translations are never touched by `--rewrite`. langsync sends only the language part to Google (`es-419` goes as `es`), so the Latin American wording is fixed in review.
- **Codegen:** a Gradle task in `:core` turns `en.json` into `object L` with typed accessors (`L.onboardingSkip`, `L.videosHidden(count)`), so a missing key fails the build.
- **`Translator`:**
  - loads catalogs from the classpath and falls back to English one key at a time;
  - a small ICU subset (`{arg}`, `plural`, `select`) with CLDR plural rules for en, es, pt, hi and ml, and no ICU4J;
  - a locale-aware formatter for sizes, durations, dates and numbers;
  - ISO 639 track-language names shown in the UI language (`Locale("de").getDisplayLanguage(active)`).
- **Resolution, the same on every device:**
  1. the saved `LANGUAGE` key in `SettingsStore` (empty means system);
  2. otherwise the system list, matched by language and then region (`es-CL` → `es-419`, `pt-PT` → `pt-BR`);
  3. otherwise English.

  `SettingsStore` is shared already; the desktop reads it via `DesktopPlatform.kt:47`.
- **Compose:** `LocalStrings` in `ui/src/shared`, fed by a `StateFlow`, so a language change recomposes with no restart. Text outside Compose (notifications, notification channel names refreshed on change, `TrackPickerFragment`, the tray, Windows notifications and SMTC) reads `Translator`.
- **Android:**
  - `res/xml/locales_config.xml` plus `android:localeConfig`;
  - `LocaleManager.setApplicationLocales` on API 33+;
  - `values-<tag>/strings.xml` for `app_name`;
  - `PhoneCountries.kt` names via `Locale.getDisplayCountry`.
- **Track defaults tie-in:** track choice runs last pick for this series → user preference → UI language. The existing per-series memory stays first.

### 2.3 App shell additions
- **What's new after an update:** store `lastSeenVersion`. On the first run of a new version, show a dismissible sheet with the bundled release highlights, written into the catalog so they are translatable. Settings gets "What's new" and "Changelog" (a link).
- **Feedback:** Settings → "Report a problem" opens a prefilled GitHub issue URL (version, device, OS, language; no personal data), or a mailto link as fallback. On TV it shows a QR code for the URL, reusing the QR component in `:ui`.
- **About:** links to the Telegram channel and group, Discussions, Sponsors and Buy Me a Coffee, Help translate, Licence; on TV these show as QR codes.
- **Rating or star prompt:** after 10 completed plays, once, dismissible: "Star TMPlayer on GitHub". It never repeats. (Optional; it is in the checklist.)

### 2.4 Player gaps (Android `PlayerActivity` with Media3; desktop `MpvPlaybackEngine`)
- **Subtitle and audio delay** in ±0.1 s steps, shown in the track menu. Android: Media3 text offset via a `SubtitleView` timing shim, and an audio offset via an `AudioProcessor`. Desktop: mpv `sub-delay` and `audio-delay`. Remembered per file.
- **Subtitle style:**
  - size S/M/L/XL, background box, position;
  - a live preview, in Settings and the player menu;
  - replaces the fixed `0.065` (`PlayerActivity.kt:449`) and `sub-font-size` 46 (`MpvPlaybackEngine.kt:85`).
- **Volume boost / night mode:** a gain and compressor `AudioProcessor` on Android, beside the existing PCM buffer work; mpv `volume-max=150` plus `af=dynaudnorm` on desktop.
- **Sleep timer / "still watching?":**
  - after N autoplayed episodes or 2 h with no input, a full-screen "Still watching?" card that pauses and stops downloads;
  - a sleep timer in the player menu, not on screen (keeps the 1.16.0 decision);
  - everywhere.
- **Next-up card on TV:** port `buildNextUpCard` to the TV branch with D-pad focus on "Play now".
- **Resume rules (Kodi model):**
  - no resume point in the first 3 min or the last 8 %, watched at 90 %;
  - save the tracks, speed and delay with the position, every 10 s as well as on pause and quit;
  - check `ResumeRecord.kt` first and only fill the gaps.
- **Desktop extras:** frame step (`.` `,`), screenshot (`s`), A-B repeat, chapter navigation, and the `?` sheet updated. Desktop frame-rate matching is out of scope.
- **Trickplay:** thumbnails from the already-downloaded range only. Android uses `MediaMetadataRetriever.getScaledFrameAtTime(OPTION_CLOSEST_SYNC)`; desktop uses a second mpv instance or an mpv screenshot at a position. Off on devices with ≤1 GB RAM. This comes last in the player track, behind a setting.

### 2.5 Browse and UX
- **Series view:**
  - `MediaName.kt` already parses SxxEyy. Group files in a chat by series key into one tile ("Show · 2 seasons · 18 eps").
  - Opening it gives season tabs and an episode list with progress and watched ticks.
  - Phone uses a bottom sheet for seasons; desktop uses a dropdown.
  - A grid toggle switches between "Series" and "All files".
  - Extend the parser with `1x02`, `Ep 02`, the anime `- 02` form, and the Telegram caption as a second source, with unit tests built from real names.
- **Home:** a new first destination on every device.
  - **Rows:** Continue (thumbnails and progress), then one row per favourite chat with its latest videos, then "Recently added across chats".
  - **Loading:** rows load lazily, 10 items each, keeping memory flat on 1 GB sticks.
  - **Navigation:** the rail and drawer keep their tabs.
- **Detail panel:** on OK-hold, the info key, right-click or a long press. It shows:
  - the cleaned title, the full filename and the caption as the synopsis;
  - resolution, codecs, tracks and size;
  - Resume `34:10` / Start over, Download, Mark watched;
  - the TMDB poster and overview when enabled.

  It is a side pane on desktop and TV, and a sheet on phone.
- **Search:**
  - recent searches, the last 5 shown as chips;
  - a "Videos in all chats" scope through TDLib `searchMessages` with a video filter;
  - results split into Chats and Videos.
- **Empty and error states with actions:**
  - "N videos hidden by size limits [Show them]";
  - "Telegram is slow to answer [Retry]";
  - a first-load tip.

  These go through `StateScaffold` and `UiState`.
- **Downloads:** a "Remove after watching" toggle, and "x GB free" on the download action.
- **TV polish:**
  - a 1.05 focus scale on tiles;
  - a check of the 48/27 dp overscan margins;
  - content descriptions for the 54 null-labelled icons (decorative ones stay null on purpose; actionable ones get labels).
- **Android TV Watch Next (optional):** `androidx.tvprovider` `WatchNextProgram` for CONTINUE and NEXT entries. It works on stock Android TV launchers and is retired on Google TV in 2027, so it is behind a setting.

### 2.7 Online metadata (zero-cost design, researched 2026-10-05)

**Facts that shape the design**
- **OpenSubtitles.com REST v1:**
  - **Key:** free, one per application. The terms forbid making users enter their own key.
  - **Download quota:** charged to each user's own free account: 10 to 20 a day (official pages disagree), 5 a day per IP anonymously.
  - **Request rate:** 5 req/s per IP, login 1 req/s.
  - **Paid tiers:** only for apps paying centrally. Per-user login keeps our cost at 0 at any scale.
  - **Legacy API:** opensubtitles.org XML-RPC is shut down.
- **OpenSubtitles quality:**
  - The hash match (size plus the 64 KB head and tail) is the reliable, in-sync route. Name matching often drifts.
  - `ai_translated` and `machine_translated` are excluded by default.
  - es and pt are deep, hi is thin, ml very thin.
- **TMDB:**
  - **Price:** free for non-commercial use; "commercial" means the main purpose is revenue. Donations don't change that, but they stay voluntary and unlock nothing.
  - **Limits:** a soft cap of about 40 req/s per IP, no daily cap.
  - **Caching and termination:** cache at most 6 months; on termination, cached data must be purged.
  - **Attribution:** required.
  - **Language quality:** es and pt-BR good, hi partial, ml sparse, so English is the fallback.
- **Other free sources:**
  - TVmaze: free, no key, at least 20 calls per 10 s, CC BY-SA with attribution.
  - AniList: free, no key, about 30/min.
  - SubDL: free key, 2,000 req/day; holds the Subscene archive, better for hi and ml.

**Design (no backend, nothing for the author to pay)**
- **Subtitles (OpenSubtitles):**
  - One app key, injected by CI from a GitHub secret and never committed, so forks register their own. Dev builds without the key hide the feature.
  - The user signs in with their own free OpenSubtitles account under Settings → Online subtitles. The token is stored like other credentials, so quota is per user.
  - Search order: hash (head and tail through TDLib byte ranges, works before the download finishes), then the TMDB/IMDb id, then the parsed title and episode.
  - Machine- and AI-translated subtitles are excluded by default (a toggle with a label).
  - Language: subtitle preference, then the UI language.
  - Show "N of M downloads left today" from `remaining` and `reset_time`.
  - Optional SubDL fallback for hi and ml, behind a user-entered SubDL key (allowed by SubDL).
- **MalayalamSubtitles.org / MSone (issue #5):**
  - **The site:** a volunteer group with about 3,400 releases, slugs of title plus year, the IMDb id on every page, and direct `.srt` downloads through `?wpdmdl=`.
  - **No permission:** the WP REST API is blocked (403), there is no published reuse licence, the group claims ownership, and it ships its own apps.
  - **Decision (user, 2026-10-05):** nothing MSone-related is built for now, not even a link-out. The user emails MSone and waits for a reply.
  - **If they agree:** an in-app MSone provider (search by title and year or IMDb id, pick the episode inside season packs, download through `?wpdmdl=`, a "via MSone" credit). It gets its own phase after P12.
  - **Never** a scraper built without that agreement.
- **Metadata:**
  - **Providers:** TMDB (built-in CI key, which the user can override in Settings), TVmaze for episode data (no key), AniList for anime (no key).
  - **When it runs:** off by default, turned on in Settings or from the detail panel.
  - **Matching:** a cleaned title (Part 2.5 parser strips release tags) plus the year or SxxEyy; `{tmdb-123}` in a filename forces an exact match.
  - **Language:** the UI language, with English fallback.
  - **Credits:** About shows the TMDB notice and logo (less prominent than TMPlayer's own branding) and the TVmaze link.
- **Shared:**
  - on-device cache keyed by file id or hash, with a TTL of at most 6 months and a purge-all action;
  - single-flight requests per item, a debounce, and backoff on 429;
  - posters fetched at the right size into the existing image disk cache.
- **Degradation:**
  - On 401/403 the provider is disabled, cached data is kept, and the user sees "Online subtitles unavailable right now" or "Add your own TMDB key".
  - A revoked OpenSubtitles key is replaced by an app update; a user-entered OpenSubtitles key is not allowed by its terms.
  - Nothing else in the app depends on these providers.
- **Known risk:** any key shipped inside the app can be pulled out and abused, then revoked. The mitigations are the CI-injected key, rotation through updates, and the TMDB user-key override.
- **Provider set confirmed by the user (2026-10-05):**
  - OpenSubtitles, with the user's own login;
  - TMDB, optional, with a user-key override;
  - TVmaze and AniList as no-key fallbacks;
  - SubDL optional and off by default;
  - OMDb, Trakt, Fanart.tv, SubSource and Wyzie skipped.
- **The user's requirement: no feature may stop working midway.** The plan enforces it as follows:
  - no core feature depends on an online provider;
  - fetched results stay cached on the device for up to 6 months;
  - fallbacks are chained: TMDB → TVmaze/AniList → filename; OpenSubtitles → SubDL (if set) → local `.srt`;
  - clear "unavailable" states instead of silent failures;
  - keys come from CI secrets and are rotated through updates;
  - the app and site call these "online extras" and never promise them as core.

## Part 3. How the bulk work is done (scripted)
1. **Find:** `grep -rnoP` per module for `Text("`, `text =`, `label =`, `title =`, `contentDescription =`, toasts and notifications, written to a scratchpad TSV.
2. **Name:** a script turns that into keys, which I review once per module.
3. **Catalog:** `jq` merges into `en.json` (sorted). Only `en.json` is written by hand or script; other locales come from langsync.
4. **Replace:** `perl -pi -e` / `sed -i` on exact call shapes, plus `sed` for imports.
5. **Check:** build, `git diff --stat`, then re-grep. Leftovers go to an allowlist or the manual list (interpolations, plurals, concatenations, Views, words needing two translations).
6. **Site:** the same method (`perl` adds `data-i18n`, `jq` writes `site/i18n/en.json`).
