## Old-Chromium test rig (answer to "test webOS and others on the connected TV")

- The Mi TV stick (Android 9, 1 GB, armeabi-v7a, low RAM) runs WebView 138 as an update. Its system
  image holds **WebView 81.0.4044.111**, one step above webOS 6's Chromium 79.
- `adb shell pm uninstall-updates com.google.android.webview` falls back to 81. Play Store updates it
  again, so it is reversible. Chromium 68 or 79 would need an APK (32-bit) set as the WebView
  implementation in Developer options, if the TV firmware shows that menu.
- `private/tvweb/build.sh` builds the test wrapper (opens `https://web.tmplayer.org/?tv=1` or any
  address; remote debugging is on in `MainActivity.java:35`). A debug page can be driven over
  `adb forward` and CDP.
- What it proves: syntax and API support, mtcute, wasm, the mediabunny repack and MSE on an old
  engine, and speed on a 1 GB, slow CPU. What it cannot prove: webOS Starfish or Tizen AVPlay codec
  support (Android WebView uses MediaCodec), TV remote key codes, or the real TV's memory limits.
  Codec truth needs a real LG or Samsung TV, or LG's and Samsung's simulators for layout only.
